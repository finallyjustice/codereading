


WCE是设备返回的.

WCE=0 就是 writethrough
设备向内核承诺: 每个写请求成功完成时, 数据都已持久化, 所以内核不需要再为这次写额外发 FLUSH/FUA.

WCE=1 就是 writeback
普通写请求成功完成时, 数据可能仍在设备易失缓存中, 不保证已持久化。需要持久化时, 内核必须使用 FLUSH/FUA.


- FLUSH: 单独的命令, 要求之前已完成的写持久化.
- FUA: 附在 WRITE 上的标志, 要求本次写持久化后才能完成.

不支持原生 FUA 的设备, Linux 可以用 WRITE -> FLUSH 实现同样的持久化要求.

----------

cache.direct=on       绕过 host page cache, 不代表持久化
cache.no-flush=off    正常执行持久化请求, 不忽略 flush, 主要测试用
write-cache=on        告诉 VM: writeback; 普通写不保证持久化
write-cache=off       告诉 VM: writethrough; QEMU 必须每次写持久化后才完成

关于drive:

简写                  绕过 host page cache    向 VM 提供的默认语义
cache=writeback       否                      writeback
cache=writethrough    否                      writethrough
cache=none            是                      writeback
cache=directsync      是                      writethrough

-----------

- virtio-blk: 通过 feature 声明支持缓存模式配置, guest 从配置空间的 wce 字段读取当前 write-cache 状态.
- virtio-scsi: guest 通过 SCSI MODE SENSE 命令读取 WCE 位, 获取当前 write-cache 状态.
