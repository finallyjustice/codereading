ACPI 本质上是 "固件/硬件怎么把平台信息告诉操作系统" 的一套标准.
操作系统靠它做几件事:

- 枚举硬件, 不靠老式硬编码
- 管电源状态: 开机, 关机, 睡眠, 唤醒
- 管中断和拓扑: CPU, APIC, NUMA, PCIe
- 做热插拔: CPU, 内存, PCI 设备
- 通过 AML/ASL 方法让 OS 调用固件定义的控制逻辑

如果放到你这个 QEMU 仓库里看, ACPI 的核心生成入口在 /home/zhang/codex/acpi/qemu/hw/i386/acpi-build.c:1960. x86 上它大致按这个顺序拼表:

- RSDP: 入口指针. OS 先找到它, 再去找别的表.
- RSDT/XSDT: 目录表. 相当于 ACPI 的 "索引页", 列出其他 ACPI 表地址.
- FADT/FACP: 固定功能描述. 告诉 OS 电源管理寄存器, SCI, 中断, 复位寄存器, 并指向 FACS 和 DSDT.
- FACS: Firmware ACPI Control Structure. 给固件和 OS 做运行时协作用, 不含 AML.
- DSDT: 最重要的 AML 表. 平台主设备树和方法都在这里, 比如 _STA, _CRS, _PRT, _EJ0.
- SSDT: 补充 AML 表. 常用于 CPU/内存/热插拔/NUMA 的增量描述.
- MADT/APIC: CPU 和中断控制器拓扑.
- MCFG: PCIe ECAM 配置空间描述.
- SRAT: NUMA 亲和性, CPU/内存属于哪个 NUMA node.
- SLIT: NUMA 距离矩阵.
- HMAT: 更细的内存性能/带宽/延迟拓扑.
- HPET: 高精度定时器描述.
- DMAR / IVRS / VIOT: IOMMU/virtio-iommu 相关拓扑.
- NFIT / CEDT / ERST / HEST 等: 分别给 NVDIMM, CXL, 错误记录, 硬件错误源这些高级特性用.
- WAET: Windows 相关增强提示表.

你也可以把 ACPI 粗分成 3 层来理解:

- 发现层: RSDP -> RSDT/XSDT -> 其他表
- 描述层: FADT/FACS 这类固定信息表
- 控制层: DSDT/SSDT 里的 AML 方法, 真正定义 "这个设备怎么工作, 怎么热插拔, 怎么关机"
